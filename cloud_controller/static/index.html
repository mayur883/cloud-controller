Apache HDFS Distributed Storage Topology

Fault-tolerant multi-node block replication across laboratory LAN racks

Rack-Aware Fault Tolerance & Self-Healing Architecture

Files segmented by the controller are distributed using a 2x Rack-Aware placement strategy: the primary block replica is placed on Rack 1 and its redundant replica is assigned to Rack 2. You can simulate network or hardware failure by toggling any DataNode offline using the controls above. The controller will seamlessly fail over to the secondary healthy replica during file download with zero interruption.

Laboratory LAN REST API & CLI Integration

Interact with the Cloud Controller programmatically from Python, shell scripts, or laboratory workstations.

1. Authenticate & Obtain JWT Token
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "alice", "password": "labpassword123"}'
2. Upload & Segment File with AES-256-GCM
curl -X POST http://localhost:8080/api/v1/files/upload \
  -H "Authorization: Bearer <TOKEN>" \
  -F "file=@experiment_data.csv" \
  -F "block_size=1048576" \
  -F "encrypt=true"
3. Download with Transparent Reassembly & Decryption
curl -X GET http://localhost:8080/api/v1/files/<FILE_ID>/download \
  -H "Authorization: Bearer <TOKEN>" \
  -o restored_experiment_data.csv
4. Inspect Distributed HDFS Block Segments
curl -X GET http://localhost:8080/api/v1/files/<FILE_ID>/blocks \
  -H "Authorization: Bearer <TOKEN>"
